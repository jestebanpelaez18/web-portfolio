Summary

HSL publishes realtime data for Helsinki's public transport as GTFS Realtime feeds, encoded in Protobuf. This project takes that feed through a medallion architecture.

Raw data lands in Azure Blob Storage. PySpark parses it and loads clean tables into PostgreSQL. dbt models the analytics layer with automated tests, and a SparkML model uses the history to predict skipped bus stops. Airflow runs the whole chain.

Highlights

Orchestrated end to end

Airflow DAGs across containerized services, with backfill and retry support for reprocessing past data.

Reruns without duplicates

Writes into PostgreSQL are idempotent, so rerunning a task or a backfill leaves the same result.

Quality checks in the model layer

dbt schema tests and data quality checks across 100k+ records: nulls, value ranges and consistency rules.

Nested feeds, parsed properly

Python and PySpark jobs unpack nested Protobuf messages and cope with schema drift, with structured logging.

Will the bus skip this stop?

With the history modelled in the Gold layer, I trained a SparkML Random Forest (50 trees, max depth 5) to predict whether a bus will skip a stop.

Evaluated on historical trip data, it reaches an AUC of 0.92.

When something breaks

Failures get traced from the Airflow task logs down to the container and the code. Because writes are idempotent, fixing the cause and rerunning the task is safe.
